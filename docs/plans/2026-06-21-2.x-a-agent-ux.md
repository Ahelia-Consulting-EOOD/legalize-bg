## Decision Records (the "brainstorming outcomes", documented per full-autonomy grant)

### D-FR-018 — article ranges: add a `get_articles` tool; make `get_article` reject ranges explicitly

**Fork (from FR-018):** (a) `get_article` returns `list[ArticleEntry]` on a range, vs (b) a new `get_articles` tool.

**Decision: (b), refined.**
- **Add `get_articles(law, articles, date=None)`** returning a single dict `{law_id, articles: [{article, paragraph, text, text_hash}, ...], commit_hash, warnings}`. Handles both a single spec and a range. One shared `commit_hash`/`warnings` channel (all entries share the law+date → same version).
- **`get_article` stays single-article** (response shape 100% unchanged — no breaking change to successful responses). When the spec parses to a **range** (`spec.range_end is not None`), it now **raises `INVALID_ARTICLE_SPEC`** with a bilingual hint pointing at `get_articles`, instead of silently returning only `article=14` (the FR-018 bug). Converting a silently-wrong result into an explicit, actionable error is a strict improvement; the docstring already warned callers of the 1b.1 limitation.

**Why not (a):** a tool with a polymorphic return (dict-or-list) has an ambiguous output schema; "always list" is a breaking change to every existing single-article caller. (b) is additive → `tools.json` 1.1.0 → **1.2.0**, no taxonomy growth.

**Range semantics:** `"чл. 14-16"` expands to every article in the act whose `_legal_article_sort_key` lies in `[key(14), key(16)]` inclusive — so it correctly includes `14, 14а, 14б, 15, 16`, not just the integers. Reuses the existing legal-number sort. Missing articles in the range are skipped (an agent asking 14–16 wants what exists); if NONE exist, raise `ARTICLE_NOT_FOUND` with `available_articles`. Ranges never carry a paragraph (the `_FULL_RE` regex makes range and `ал.` mutually exclusive).

### D-FR-stemmer — defer the aggressive Bulgarian stemmer out of 2.x-a (→ FR-021, D-032)

**Decision: no `bg_normalize` change this batch.** File FR-021 and a DECISIONS entry; refine the `_BG_DEFINITE_SUFFIXES` rationale comment.

**Why:** the canonical open case is `българският` (masc adj, consonant stem) vs indefinite `български`. The definite long-form `ият` rule already strips `българският → българск`, but the **indefinite** `български` ends in bare `-и` and is left intact → the two forms still diverge. Closing the gap requires stripping bare `-и`, which also mangles plural nouns (`закони`, `поръчки`) and collides with the already-REJECTED `ия`/`ите` suffixes (`решения → реше`). That is genuinely a POS-aware morphology problem, solvable only by a real stemmer. A real stemmer:
1. **Conflicts with D-022** ("No external NLP libs; pure Python") — adding `snowballstemmer`/`PyStemmer` would supersede a foundational design decision (owner-ratifiable, not a quiet default).
2. **Is applied symmetrically across the whole corpus** → forces a full re-index and risks the carefully-tuned, locked ranking behavior (two-tier title match, FR-015 synonym + rang-tier sort, FR-013 `новият→нов`).
3. **Needs a full-corpus regression eval harness** (precision/recall over real queries) before it can be trusted — a sub-project, not a batch item.

Shipping a half-measure (e.g. stripping `-и`) would regress precision for narrow recall gains. The responsible call is to scope the stemmer as its own FR with an eval gate. This is the documented default, surfaced for owner review in the PR.

### D-FR-011 — degenerate acts: categorize + waive, do not invent data

**Re-count (live 3,599):** 7 empty-titulo (all numeric-slug §7.3 phantoms; already handled by the `<doc_id=N>` substitute) ⊂ 121 null-`fecha_publicacion`. The 2026-06 re-scrape did NOT change these counts.

**Decision:** the dominant null-pub population is **municipal council ordinances** (`наредба на ... общински съвет`) + 2 judicial ethics codes — acts with *legitimately* no Държавен вестник issue, so a null publication date is **correct**, not broken. Backfilling would fabricate data. Deliverable: a categorized triage report (`docs/data/fr-011-degenerate-triage.md`) with a per-category disposition and a **WAIVERS** registry marking the municipally-/ethically-correct nulls as expected. Embedded-vision title/date recovery (render the source page + Read it — never an external OCR lib, per global rule) is attempted ONLY where a value genuinely exists at the source but failed to parse. No SQLite/schema change; no invented `fecha_publicacion`.

```python
def articles_lookup(conn: sqlite3.Connection, law_id: str,
                    start: str, end: str, date: str | None) -> list[dict]:
    """Return article-as-whole provision rows for every article in the
    law whose legal-number sort key is within [start, end] inclusive,
    ordered legally. Ranges address whole articles only (paragraph=None);
    suffixed articles (14а) inside the numeric span are included.
    Raises ArticleNotFound (with available_articles) when the range is
    empty for this law/date."""
    target = date or _date.today().isoformat()
    lo, hi = _legal_article_sort_key(start), _legal_article_sort_key(end)
    rows = conn.execute(
        """SELECT article, paragraph, text, text_hash, valid_from, valid_to
             FROM provisions
            WHERE law_id = ? AND paragraph IS NULL
              AND valid_from <= ? AND (valid_to IS NULL OR valid_to >= ?)""",
        (law_id, target, target),
    ).fetchall()
    in_range = [r for r in rows
                if lo <= _legal_article_sort_key(r["article"]) <= hi]
    in_range.sort(key=lambda r: _legal_article_sort_key(r["article"]))
    if not in_range:
        raw = [r["article"] for r in conn.execute(
            "SELECT DISTINCT article FROM provisions WHERE law_id = ?",
            (law_id,)).fetchall()]
        raise ArticleNotFound(law_id=law_id, article=f"{start}-{end}",
                              paragraph=None,
                              available_articles=sorted(raw, key=_legal_article_sort_key))
    return [dict(r) for r in in_range]
```
