# Preflight: FR-020 — multi-version `law_versions` from git history (time-machine)

Filed 2026-06-21. Template: `docs/process/IMPLEMENTATION-PREFLIGHT.md`.

- **protected surface:** 6 (Index Builder + FTS Normalizer) — and touches the temporal semantics behind Surface 3 tools (`diff`, `get_law(date)`, `history`).
- **authoritative source:** Surface 6 (`.ahelia/protected-surfaces.yaml`); `docs/data/schema-reference.md` §2 (INCLUSIVE `valid_to`); D-031 (honest single-version semantics — **superseded** by this change).
- **hard constraint confirmed:** yes. `bg_normalize` UNCHANGED; idempotent/rebuildable; `provisions` article+alinea (D-023) UNCHANGED; FTS5 tokenizer UNCHANGED. SQLite schema UNCHANGED (no new columns — `law_versions` already has `law_id, valid_from, valid_to, commit_hash, date_uncertain`).
- **what is changing:**
  1. **`index/build.py` law-versions population:** instead of ONE `law_versions` row per act (`valid_from`=frontmatter date, `commit_hash`=HEAD), insert **one row per git commit** of the act's file: `valid_from`=commit author-date (the legislative/DV date per the commit-date discipline), `commit_hash`=that commit, `valid_to`=day before the next version's `valid_from` (NULL for the latest). The latest row's `commit_hash` is HEAD (working-tree fast path preserved). **Perf:** the full build derives the whole-corpus map in ONE `git log --name-only` pass (`_all_file_versions`), NOT one `git log` per act — per-act measured ~8-20 min; single-pass is ~34 s (faster than the ~45 s baseline). No `--follow` (stable slugs → no renames; sort handles ordering). The FR-014 incremental path uses a per-act `git log` for its few changed acts. Falls back to the single-row behavior when an act has no git history (e.g. test corpora without commits) so existing tests/fixtures keep working.
  2. **`date_uncertain`:** preserved per the §7.2 frontmatter rule — set on the act's version rows when the frontmatter publication date was absent (the existing condition), so the DATE_UNCERTAIN warning contract is unchanged.
  3. **FR-014 hazard fix (now reachable):** the incremental pointer-bump `UPDATE law_versions SET commit_hash=HEAD WHERE commit_hash=base` (D-040/D-041) would corrupt historical rows once multiple versions exist. Scope it to the CURRENT version only (`WHERE valid_to IS NULL`), matching how incremental re-indexes a changed act (delete its rows, re-derive from git log).
- **query layer:** UNCHANGED — `version_at_date` already selects the in-force version via `valid_from<=date AND (valid_to IS NULL OR valid_to>=date) ORDER BY valid_from DESC`; `get_law`/`diff` already branch to `git show`/`git diff` for non-current commits. They light up automatically once multiple rows exist (the D-031 note's "write-side accumulates more versions").
- **violation risk:** wrong `valid_from`/`valid_to` boundaries → wrong historical version resolved. Mitigations: (a) a **real-git oracle test** — build a throwaway repo with 2+ dated commits of an act, assert `version_at_date` resolves each historical commit and `diff` returns a real diff; (b) boundary tests for the INCLUSIVE `valid_to` (the day before the next version); (c) same-day-multiple-commits edge documented; (d) no-git-history fallback keeps existing tests green; (e) idempotence retained (full rebuild re-derives identically).
- **allowed scope confirmed:** yes — Surface 6 additive build-path change preserving idempotence + symmetry + D-023; no schema change; no `bg_normalize` change → no waiver.
