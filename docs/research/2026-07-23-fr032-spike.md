# FR-032 Spike — per-segment FTS5: measurements and ratified parameters

**Date:** 2026-07-23 · **Branch:** `feat/fr032-per-article-fts` · **Design:** `docs/plans/2026-07-21-fr032-per-article-fts-design.md` (§8 mandated this spike before any query-layer work)
**Method:** prototype span-based segmenter + `articles_fts` + title-only `laws_fts_v2` built into a COPY of the live `catalog.db` (3,602 acts); throwaway scripts (session scratchpad), logic re-lands TDD'd in `index/segments.py`. Cold = fresh `mode=ro` connection; warm = median of 5 on the same connection; quiet machine, OS page cache not purged (same convention as `scripts/perf_probe.py`).

| Coverage invariant (`concat(spans) == body`) | **0 failures / 3,602 acts** |

Span-tiling makes the coverage invariant hold *by construction* (segments are offset
ranges over the body; nothing is re-assembled). The 125 zero-provision acts index as
single `other`/`para`/`annex` segments — recall preserved.

## 2. Tier-2 SQL form (design Decision 3: "prototype decides once")

- **`MIN(bm25(t))` inside GROUP BY fails outright** (`unable to use function bm25 in
  the requested context`) — the design's Form A as sketched does not run on sqlite3,
  and a plain subquery gets flattened back into the same error. It runs only as a
  `WITH hits AS MATERIALIZED (...)` CTE.
- The MATERIALIZED form computes `snippet()` for **every** matching segment: broad
  terms pay 700–1,050 ms cold. Rejected.
- **Form B (overscan) wins**: plain `ORDER BY bm25(articles_fts) LIMIT 500`,
  act-level dedup/aggregation in the host language. Trivially D1-portable (no
  aggregate-over-aux-function, no CTE), snippets computed only for emitted rows.

**Fixed window, not K×limit:** the overscan LIMIT is a constant **500** so the
breadth count below (and hence every score) is deterministic and independent of the
caller's `limit` — a parity and testability requirement.

## 5. Ranking: short-segment bias found; Q1 AMENDED by owner (2026-07-23)

Plain MIN-of-bm25 (ratified Q1) exhibits a strong short-document bias — bm25 length
normalization lets a 242-char § with one incidental co-occurrence outrank the
canonical act:

- "трудов договор": **Кодекс на труда at raw rank 31** (v1: rank 1), below dozens of
  tiny segments; rang-tier sort cannot rescue it (outside the dedup window).
- "административни нарушения": **ЗАНН at raw rank 6** behind five irrelevant acts.

Fix measured: breadth-corrected best-segment score,
`score = best_bm25 − α·n/(n+5)`, `n` = act's matching segments within the fixed
500-row window. The rational form (not `ln`) is deliberate: pure arithmetic is
float-identical across CPython/libm and V8/fdlibm, preserving cross-plane
float-exact parity; `ln` risks last-ulp divergence.

| Query | plain MIN | α=4 rational |
|---|---|---|
| административни нарушения | ЗАНН #6 | **ЗАНН #1** |
| трудов договор | КТ #31 | **КТ #3 (after rang sort)** |
| обществени поръчки (body tier) | ЗОП #3 | **ЗОП #1** |
| енергийна ефективност / лични данни / касови апарати | stable | stable (или strictly better: Закон за енергетиката enters top-5) |

α=4 vs α=6 orderings were near-identical (saturating form is insensitive) — **α=4**
chosen as the minimal effective value.

**Owner decision (2026-07-23, this session): Q1 amended** — tier-2 act score =
best-segment bm25 **plus the rational breadth correction (α=4, window 500)**.
Recorded as a D-056 amendment; the full-pipeline golden-diff table remains a PR
review gate.

## 6. Parameters ratified for implementation

| Parameter | Value | Basis |
|---|---|---|
| Tier-2 SQL form | overscan, `ORDER BY bm25 LIMIT 500`, host-side dedup+scoring | §2 |

| `_TIER2_MIN_TITLE_HITS` | 3 (unchanged, D-051) | design Decision 3 |
